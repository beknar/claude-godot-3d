# CLAUDE.md

Working notes for Claude Code in this repository. `README.md` is the player/creator guide;
this file covers how the game is built, how to operate and test it, and what to watch out for.

## Project at a glance

A Godot **4.7** game (GL Compatibility renderer, Jolt physics): a comic-styled space fighter,
modelled after a reference illustration, flown over procedurally generated rolling hills.
A second level (`game/person_level.tscn`) has a playable winged cyborg girl, also built after
a reference illustration, who walks, runs, jumps and flies. A third (`game/fig1_level.tscn`)
walks an imported woman figure (rigged by our scripts) through a generated city street.
Everything is built in-engine or generated by `tools/`, with two exceptions: the engine hum,
a Pixabay recording (credited in README.md), and the woman figure `fig1/woman-model.glb`, a
static mesh that `tools/` rigs and animates.

- Godot executable on this machine: `C:\Users\kestanol\Desktop\Godot_v4.7.2-stable_win64.exe`
  (`_console.exe` beside it for headless runs). The Desktop also holds older versions; the
  godot-ai plugin needs 4.7+, so don't open the project in 4.6.1 or earlier.
- Main scene: `res://game/flight_level.tscn`.
- Autoloads: `WindowControls` (F11 / Alt+Enter fullscreen) and `_mcp_game_helper` (added by the plugin).
- Git remote: `https://github.com/beknar/claude-godot-3d` (public), branch `main`.
- The editor is usually open with the **godot-ai** MCP server connected (`addons/godot_ai`,
  tools `mcp__godot-ai__*`). Prefer it for scene edits, running the game, screenshots, logs
  and live inspection. `addons/godot_ai` is third-party (MIT): don't edit it.

## How the systems work

### Fighter model (`fighter/fighter.tscn`)

**Coordinates:** fighter-local space with nose toward **−Z**, up **+Y**, right **+X**, origin
roughly mid-body. The nose tip is at z −6.2, the wing arms are at x ±3.6 and the engines sit
at (±2.3, 1.1, 0.8). About **2,460 triangles**; re-check with the counter after geometry changes.

**Hull parts** (`Fuselage`, `Chin`, `Canopy`, `SpineHump`, `ArmL/R`, plus the single-extrusion
`WingRoot`):
- Each is a `CSGCombiner3D` that **intersects** three extruded `CSGPolygon3D` outlines:
  - `SideProfile`: rotated Y 90°; polygon (x, y) = (−z, y).
  - `TopProfile`: rotated X −90°; polygon (x, y) = (x, −z).
  - `FrontProfile`: polygon in XY, extruded along Z.
- Reshape a part by editing its polygons; chamfers are extra polygon corners.
- `ArmR` mirrors `ArmL`; keep them in sync.

**Primitive parts:**
- **Engines:** `Body`, `CowlFront`/`CowlRear` (bulge), torus `IntakeLip`, `Intake` disc,
  `Nozzle`, `NozzleCore`, `ExhaustTrail` cone, `Pylon`.
- **Arm tips:** cannons.
- **3D clutter:** `SpineDetail`, `CockpitDetail`, `Details` (nose guns).
- Cylinders use `rings = 0`; extra rings cost triangles and add nothing.

**Drawn-on detail:** vents, hatches, panels, markings and canopy frames are drawn by the
shaders (*surface features*), not modelled.

**Position-coupled data** must move with the geometry:
- Feature boxes in `hull_body.tres` (fuselage + hump), `hull_chin.tres`, `hull_wing.tres`
  (arm-local), `hull_root.tres` (wing-root local, rotated) and `canopy_glass.tres`. All are
  object space of the CSG root that uses them.
- Nacelle trim `bands` in `nacelle.tres` (engine-body local Y).
- `ExhaustParticlesL/R` in `game/flight_level.tscn` (at the nozzles: ±2.3, 1.1, 2.7).

**Name contracts:**
- `fighter_controller.gd` stretches nodes named `ExhaustTrail`.
- `fighter_livery.gd` repaints any ShaderMaterial with a `base_color` (hull) or `body_color`
  (nacelle) uniform.

### Materials (`fighter/materials/`)

- **`hull_panels.gdshader`:** a triplanar, object-space sample of the packed panel map
  (`panel_map`, `tile_size` = metres per repeat), then surface features, cel lighting and bump.
  Packed channels: R inset plate, G ink line, B tone (> 0.9 = striped decal), A height.
  Colours come from uniforms (`base_color`, `plate_dark`, `line_color`, `marking_color`).
- **`nacelle.gdshader`:** the panel map wrapped once around a cylinder (axis = local Y), plus
  trim `bands`.
- **`canopy.gdshader`:** glass with painted frame features.
- **Others:** `intake_grille.gdshader` (fan blades + glowing core, `outer_radius` must match
  the intake disc), `exhaust.gdshader` (additive trail) and `starfield.gdshader` (sky).
- **`detail_lib.gdshaderinc`**, shared:
  - `bump_normal()`: tangent-free bump mapping.
  - `#define CEL_SHADING`: the two-tone `light()` function. `cel_light_scale ≈ 0.3` matches
    Godot's 1/π Lambert, so leave it there unless you mean to change brightness.
  - `#define DETAIL_FEATURES`: up to **12** feature boxes per material.
    - `feature_center` = xyz + kind (0 paint, 1 raised, 2 recessed, 3 vent, 4 hatch).
    - `feature_size` = half-extents xyz + relief (m).
    - `feature_color` = rgba, where alpha is coverage.
    - The box's thinnest axis should face along the surface normal.
- **Plain materials** (no features): `hull_light` (engine cowls), `hull_dark` (boxes, lips,
  pylons), `gunmetal`, `nozzle_glow`, `signal_red`.

### Gameplay (`game/`)

- **Controller:** mouse delta becomes a requested pitch/yaw rate (arrows add a fixed rate),
  smoothed by `turn_response`; A/D set the roll rate. Orientation is a free basis, with no
  Euler angles. With A/D released the wings level the short way round, except near vertical.
- **Speed:** moves toward `lerp(min_speed, max_speed, throttle)` with acceleration and drag.
  The afterburner and brake override the target. Pitch adds or subtracts `dive_acceleration`.
- **Boost:** `boost_capacity` seconds of fuel. It needs `boost_relight_fraction` to light,
  and after a burnout Shift must be released before it relights.
- **Assists:** minimum clearance of 8 m over `terrain.height_at()`, a 700 m ceiling, and a
  steer-home past `boundary_radius` (1200 in the level). The low-altitude warning is below 25 m.
- **Signals:** `boost_started/ended/denied`, `brake_started/ended` and
  `ground_warning_changed(active)`, consumed by `FighterAudio`.
- **Input actions:** `fly_pitch_up/down`, `fly_yaw_left/right` (arrows), `fly_roll_left/right`
  (A/D), `fly_throttle_up/down` (W/S, E/Q), `fly_boost` (Shift), `fly_brake` (Space),
  `toggle_fullscreen` (F11, Alt+Enter). The mouse is captured on start; Esc releases it.
- **Level overrides** in `flight_level.tscn`:
  - Terrain: `size` 4000, `resolution` 320, `hill_height` 160.
  - Player: starts at (0, 180, 350), `boundary_radius` 1200.
  - ChaseCamera: `offset` (0, 5, 20), `look_ahead` 25, `near` 1, `far` 3000.
  - Sky, fog and ambient light are a built-in Environment in the scene.
- **Terrain:** `RollingHillsTerrain` regenerates its internal (unsaved) mesh and HeightMapShape3D
  on any export change. `height_at(x, z)` matches the mesh exactly.

### Winged cyborg (`person/person.tscn`, built by `tools/build_person.gd`)

**Workflow:** change the builder, then run it headless (see *Commands*), then
`filesystem_manage scan`. It rewrites `person.tscn`, `person/meshes/{body,hair,wings}.res`
and `person_animations.tres` and prints triangle counts (about 19,600 tris, 153 bones).
Materials (`person/materials/*.tres`) are hand-written and only referenced by the builder.

**Coordinates:** metres, standing on the origin facing **−Z** (+X is her right, −X her left),
about 1.66 m tall with hair. Pelvis bone at y 0.93, head centre at (0, 1.556, −0.006).

**Skeleton:**
- Bones: `Hips` (root) → `Spine` → `Chest` → `Neck` → `Head`; per side `Left/Right` +
  `Shoulder`, `UpperArm`, `LowerArm`, `Hand`, `UpperLeg`, `LowerLeg`, `Foot`, `Toes`,
  `Wing1/2/3` (wing shoulder, elbow, wrist, all under `Chest`).
- **Feather bones:** every feather card has its own bone at its root, a child of its wing
  segment: `Primary1–9` (Wing3), `Secondary1–8` (Wing2), `Tertial1–6` (Wing1) and
  `Covert1–40` (coverts, numbered along the wing). `feather_meta` records each one's rest
  angle and folded angle (degrees from straight down, + toward the tip) for the poses.
  Flight clips leave them at identity.
- **Every rest basis is identity.** A pose rotation is a rotation in the parent's axes:
  +X bends forward (a hanging arm or leg swings forward, a head tilts up), Z swings
  sideways (−Z lifts the left arm out), Y twists. Wing poses: Y swings the wing fore/aft
  (+ toward her back = upstroke in flight), Z within the wing plane folds or raises it.
- Poses are authored for the left side; `mirror()` gives the right: quaternion (x, −y, −z, w).

**Mesh construction:** lofted cross-sections (`grid`, `tube`, `ellipsoid`, `torus`),
armour as thick shells (`shell`: outer + inner surface + flat rims). Winding is decided
per triangle against an outward hint, so mirrored parts never flip.
- **Skinning:** rigid (one bone) everywhere except the torso undersuit, which blends
  Hips→Spine→Chest by height (`torso_weights`). Feathers follow their own feather bones.
- **UV contracts:**
  - Every loft has metric UVs (u around, v along, metres). `person_panels.gdshader`
    divides by `tile_size`. Object-space triplanar like the fighter's would slide on a
    skinned mesh.
  - The head's UV is its rest head-local (x, y) and UV2.x its depth, in design units
    (divided by `HEAD_SCALE`). `skin.gdshader`'s `eye_center`, `mouth_y` etc. are in
    those units.
  - Hair locks: UV.x across the lock, UV.y root→tip.
  - Feather cards: UV.x selects one of four feathers in `feathers.png`, UV.y root→tip.
- **Hair** is kept outside the skull by `push_out()` against the head ellipsoid. Feathers
  hang from the wing frame (rest pose: wing plane vertical behind her, feathers pointing
  down; in flight she pitches forward and they trail).

**Animations** (`build_animations`):
- `idle` 2.4 s, `walk` and `run` 1.0 s (left heel strike at t = 0, same length so they
  blend in phase), `fall` 1.2 s, `hover` 0.7 s, `fly` 0.8 s, `glide` 2.0 s (the
  illustration's pose). All loop.
- `fold_wings` 1.0 s, one-shot: spread at 0, folded at 1 (play it backwards to unfold).
- `RESET`.
- Every clip keys every bone. A bone that never moves gets a single key, and Hips has a
  position track for bob.

**Wing fold** (`fold_wings(pose, f)`):
- The frame folds in a bird's Z within the wing plane:
  - `Wing1` turns `FOLD_W1` (down), then tilts `FOLD_TILT` so the lower end leans back off
    her legs.
  - `Wing2` turns `FOLD_W2` (the forearm back up).
  - `Wing3` turns `FOLD_W3` (the hand down again).
- It's staged: shoulder from f = 0–0.6, forearm 0.15–0.8, hand 0.3–0.95, feathers 0.25–1,
  with a ruffle as it settles.
- Each feather's own turn = rest angle − the chain's turn so far − the wanted angle, so the
  fan collapses into a stack pointing down her back.
- `idle`, `walk`, `run` and `fall` use the fully folded pose.

**Level controls** (`PersonController`):
- **States:** `GROUND`, `AIRBORNE` (jump or fall) and `FLYING`.
  - Space jumps, and a second press mid-air flies. F takes off, or drops out of flight.
  - In flight, Space climbs and C/Ctrl descends; Shift runs, or flies fast and glides.
  - Touching the floor while not rising lands her.
  - `boundary_radius` (600) turns her back before the 1.6 km terrain's edge.
- **Model:** `ModelPivot` (y 1.0) yaws to her velocity and, in flight, pitches forward
  with speed (up to `max_flight_pitch_deg`) and banks with turn rate.
- **AnimationTree:** built in code under the Person instance:
  - `ground` BlendSpace1D (idle 0, walk 1, run 2) → `ground_scale`
  - `airborne` Blend2 with `fall`
  - `air` BlendSpace1D (hover 0, fly 1, glide 2) → `air_scale`
  - `mode` Blend2 between the ground side and the air side
  - `wings` Blend2, filtered to the wing and feather bones:
    - input 1 is `fold_wings` → `fold_seek` (TimeSeek) → `fold_hold` (TimeScale 0).
    - The controller scrubs it with `_wing_fold` (0 spread, 1 folded): toward 1 whenever
      she isn't flying (`fold_time` 0.9 s) and toward 0 on take-off (`unfold_time` 0.35 s).
    - The layer weighs 1 only while the wings are moving. At rest the ground and flight
      clips hold the same folded and spread poses, with their own motion.

  `ground_scale` is the cadence that matches the strides (`walk_stride` 1.6 m,
  `run_stride` 3.6 m per cycle).
- **Input actions:** `move_forward/back/left/right` (WASD), `move_run` (Shift),
  `move_jump` (Space), `move_descend` (C, Ctrl), `move_fly` (F).

### Woman figure (`fig1/`) and the city level

**Rig pipeline** (only the scripts are hand-edited):
1. `tools/rig_fig1.py` (Blender, headless):
   - Input `fig1/woman-model.glb`: a single static mesh, 1 unit tall, facing glTF +Z.
   - Scales it to 1.70 m with the soles at 0 and builds 21 bones at the measured joint
     table `J` (glTF axes; her left is +X there).
   - Binds the mesh with `ARMATURE_AUTO` (bone heat) and gives any unweighted island to
     its nearest bone.
   - Exports `fig1/woman_rigged.glb`.
2. Let the editor import that glb (`filesystem_manage scan`) **before** step 3.
3. `tools/build_fig1.gd` (Godot, headless):
   - Reads the skinned mesh and computes each vertex's rest position from the binds.
   - Turns her 180° to face −Z and rebuilds the skeleton with identity rest bases (same
     convention and bone names as the cyborg, minus wings).
   - Remaps the bone indices and saves the scene, mesh, material and animations.

**Joints:** the model stands with her left leg angled out, her left foot forward and her
arms close to her body, so the joints aren't symmetric. To move one, edit `J` in
`rig_fig1.py`. A front/side vertex scatter with the joints marked is the quickest check.

**Neutral stance:** `NEUTRAL_DIRS` gives target directions for the legs and arms, and each
bone gets a global shortest-arc rotation N toward its target. Pose rotations act in that
straightened frame: local = N_parent⁻¹ · pose · N_bone. Multiplying the local neutral
instead bends the joints about twisted axes, and the arms stop mirroring. `hips_drop`
re-seats the soles on the floor.

**Clips:**
- `idle` 3.0 s, `walk` and `run` 1.0 s (left heel strike at t = 0), `jump` and `fall`
  (looping air poses), and `land` (0.4 s one-shot crouch).
- The walk is a heels walk: shorter stride, feet crossing toward the midline, hip sway.

**WalkerController:**
- Moves relative to the camera's `get_yaw()`.
- Jumping: `coyote_time` 0.12 s (a jump still works just after stepping off an edge) and
  `jump_buffer` 0.15 s (a press just before landing still jumps).
- AnimationTree, built in code:
  - `ground` BlendSpace1D (idle, walk, run) → `ground_scale` (stride cadence:
    `walk_stride` 1.35 m, `run_stride` 3.2 m)
  - `air` BlendSpace1D (jump 0 → fall 1, by vertical speed)
  - `airborne` Blend2 between the ground side and `air`
  - `land` OneShot, fired when landing faster than `hard_landing_speed`

**CityStreet** (`@tool`; all generated nodes sit under one internal `Generated` child):
- **Layout:** the street runs along X. Driving lanes are `lane_width` wide on each side of
  z = 0, then parking lanes, kerbs at |z| = `road_half_width()`, then sidewalks and buildings.
  Traffic drives on the right: +X in the lane at +z.
- **Kerbs:** the step has a ConvexPolygon ramp collider, so a CharacterBody3D climbs it.
- **Lights:** the road and sidewalks are 20 m segments, because Compatibility caps lights per
  mesh (8) and each segment should pick up its nearby lights.
- **Ends:** buildings close off both ends, with invisible walls at ±(length/2 + 6). Driving
  cars wrap at ±(length/2 + 20), hidden in the fog.
- **Camera support:** `height_at()` gives the walking-surface height, for OrbitCamera's
  terrain clamp.

**StreetCar:**
- An AnimatableBody3D with front at +X (cars driving toward −X are turned round).
- `cruise_speed` 0 makes a parked car.
- Driving cars slow for anything in the `player` group, or a car in their lane, within
  `safe_gap`, stop about 2 m short, and show brake lights.

**OrbitCamera:** `avoid_obstacles` ray-casts from the focus to the camera (excluding the
target) and pulls the camera in front of any hit.

### Rendering effects

- **Ink outline** (`game/fx/ink_outline.*`):
  - A full-screen quad parented to each camera. It reconstructs view positions from depth
    and inks large second differences (silhouettes and creases).
  - Bends below `noise_margin` × one depth-step are ignored, so flat faces don't speckle.
  - Its fade range is per material: the default fades at 120–350 m; the flight copy
    (`ink_outline_flight.tres`) fades at 70–140 m so terrain stays clean.
  - Close to a small figure every polygon edge exceeds the default crease threshold and
    the model looks like a wireframe. `ink_outline_person.tres` raises it (4.0 → 7.0,
    thinner lines, fade 25–60 m) so only silhouettes and plate edges are inked. Use it on
    any camera that frames the cyborg.
- **Exhaust particles:** CPUParticles3D in world space, alpha-blended so they show against a
  bright sky. The controller scales them with speed and boost.

## Operating the game (agent workflow)

- **Run:** `project_run` (mode `main`), then `editor_screenshot` with `source: "game"`.
  `project_manage stop` when done.
- **Other scenes:** `project_run` with mode `custom` and `scene` (`res://game/fig1_level.tscn`, `res://game/person_level.tscn`,
  `res://person/person_showcase.tscn`).
- **Drive input:** `game_manage input_key` with `{key, pressed}` (hold, screenshot, then
  release). Simulated mouse motion turns the ship only on the first event, so test steering
  with the arrow keys.
  - Simulated key presses can miss `Input.is_action_just_pressed()` (the cyborg's jump,
    take-off and drop). Drive those with `Input.action_press("move_jump")`, then await two
    `physics_frame`s and call `action_release`, inside `game_eval`.
  - To see the cyborg from the side while she moves, change the camera's `_yaw` and take
    the screenshot on the next frame, before she turns to follow it.
- **Pose checks:** in the showcase, `$Person/AnimationPlayer.play(name)`, `seek(t, true)`,
  `pause()`. Rotate `$Person` (e.g. −70° X) to see flight clips as she'll fly them.
- **Inspect:** `game_manage get_node_info` (`Player` exposes speed, throttle and so on) and
  `editor_manage game_eval` for arbitrary GDScript in the running game.
- **Logs:** `logs_read` with source `game` and `editor`. Check both after every change.
- **Verify a model change:**
  - `godot --headless --path . --script tools/count_triangles.gd` for the triangle count.
  - `tools/render_frame.sh res://fighter/fighter_showcase.tscn 5 out.png` for a 1080p still
    in the reference pose.
  - A turntable contact sheet for every angle: render 600 frames, then use ffmpeg
    `select='not(mod(n\,75))',tile=4x2`.
- **Reference images:** neither illustration is in the repo (public-repo concern). The
  untracked `fighter_vs_reference.png` is a local side-by-side; keep it out of commits.

```sh
uv run --no-project --with numpy --with pillow python tools/generate_textures.py
uv run --no-project --with numpy --with pillow python tools/generate_person_textures.py
godot --headless --path . --script tools/build_person.gd             # the cyborg -> person/

# turntable video: write override.cfg as render_frame.sh does, then

ffmpeg -framerate 60 -i out/frame%08d.png -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -movflags +faststart video.mp4
```

That folder is git-ignored, because the Pixabay licence forbids redistributing the raw sound;

```sh

```

## Gotchas (learned the hard way)

- **MCP `set_shader_param` mangles array uniforms**: it saves a list of dicts, or zeros a
  `PackedVector4Array`. Write those `.tres` files by hand as `PackedVector4Array(x, y, z, w, ...)`.
- **The editor caches resources.** Hand edits to a `.tres` on disk are used by separate Godot
  processes (game runs, renders), but the open editor keeps showing its cached copy. If the
  editor's copy is *modified*, running the game autosaves it over your edit. Writing a new
  filename and reassigning it avoids both problems. Strip the `uid="..."` when copying a file.
- **Project settings can be reverted** by the editor rewriting `project.godot`. After
  `project_manage settings_set`, grep `project.godot` to confirm it stuck.
  (`display/window/stretch/mode` must be `canvas_items`.)
- `filesystem_manage remove` can refuse with "UID mapping is not authoritative". Use `git rm`
  for tracked files.
- `attach_script` on a node already in the tree doesn't run `_ready()`. Save and
  `scene_open(force_reload=true)`; this matters for `@tool` scripts such as the terrain.
- After writing files on disk, run `filesystem_manage scan`. For a changed asset (audio,
  texture), `reimport` alone can leave the old import in `.godot/imported/`; the scan is what
  re-runs the importer. Check the `.sample`/`.ctex` timestamp, or the stream length in-game.
- **Movie Maker toggle** (editor top-right) silences audio and makes every run record to
  `1.avi`. If sound "disappears", check it first.
- The editor embeds the running game in its Game tab at the base size (1152×648), and the
  game can't resize its own window there (`get_window().size = …` is ignored). The Game tab's
  ⋮ menu sets the embedded sizing (Fixed / Keep Aspect Ratio / Stretch to Fit); that choice
  is per-machine editor metadata, not a project setting.
- **Depth texture in Compatibility:** reconstruct with `ndc = vec3(uv, depth) * 2.0 - 1.0`. The
  depth buffer is coarse (~16-bit), so keep camera `near` at 1–4 m; 0.05 speckles every face.
- `CSGShape3D.get_meshes()` can be stale; the counter uses `bake_static_mesh()`.
- Duplicating a node and reparenting it keeps the global transform. Reset the local
  position afterwards.
- Godot `Curve` resources clamp to 0..1 unless `max_value` is raised.
- Packed mask textures are imported lossless with mipmaps, with no VRAM compression and no
  alpha-border fix. Compression and border fixing corrupt the packed channels.
  - A **new** texture first imported by a headless run gets VRAM compression and the border
    fix. Set `compress/mode=0` and `process/fix_alpha_border=false` in its `.import`, and
    delete its `.godot/imported/<name>.png-*` files so it re-imports.
- Stop the running game before rebuilding the cyborg. The headless build can run while the
  editor is open (`filesystem_manage scan` afterwards), but the editor once vanished during
  a build that ran alongside a playing game.
- A headless Godot run that has to import a file the editor is importing at the same time
  can hang indefinitely. Import in the editor first (`filesystem_manage scan`), and run long
  headless jobs with a timeout (PowerShell: `Start-Process ... -PassThru`, then
  `WaitForExit(ms)`).
- `filesystem_manage move` refuses files over 256 KB ("Cannot safely read owner"). Move big
  assets on disk without their `.import` files, then scan so Godot re-imports them.
- In a SceneTree `--script`, nodes added during `_initialize` aren't inside the tree yet, so
  `global_transform` is invalid. Compose local `transform`s up the parent chain instead.
- GDScript in `tools/build_person.gd`: type `for` variables over literal arrays
  (`for sx: float in [-1.0, 1.0]`) and values pulled out of arrays (`var x: float = arr[i]`).
  `:=` can't infer a type from a Variant, and that's a parse error.
- Don't add hard specular to the flat hull; it lights whole panels at once. Bumped details on
  glossy glass sparkle, so canopy frames are flat paint.

## Conventions

- GDScript: typed, tabs, `##` doc comments on exports, matching the existing scripts.
- Keep generated assets reproducible: change the generator, not the output file.
- Every scene reuses `fighter.tscn`; scene-specific looks go in per-instance overrides
  (for example `FighterLivery`), not edits to shared materials.
- Don't commit `*.avi`, `*.mp4`, `override.cfg` or `fighter_vs_reference.png`.
- Commit messages end with the `Co-Authored-By` trailer; push only when asked.
