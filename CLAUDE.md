# CLAUDE.md

Guidance for Claude Code working in this repository.

## Project

A Godot 4.7 (GL Compatibility renderer, Jolt physics) game: a comic-styled space fighter,
modelled after an illustration, flying over procedurally generated rolling hills.
Everything is built in-engine: no imported 3D models, and textures and sounds are
generated by the scripts in `tools/`.

- Editor executable on this machine: `E:\Downloads\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64.exe`
- Main scene: `res://game/flight_level.tscn`
- The editor is usually open with the **godot-ai** MCP server connected
  (`addons/godot_ai`, tools named `mcp__godot-ai__*`). Prefer it for scene edits,
  running the game, screenshots, logs and live inspection (`game_manage`, `editor_manage game_eval`).

## Fighter model

Built from CSG and primitive meshes in fighter-local space: nose toward **-Z**, up **+Y**,
right **+X**, origin roughly mid-body. Engines sit at (±2.3, 1.1, 0.8). ~2,460 triangles — check with the counter below
after geometry changes.

- Main hull shapes (`Fuselage`, `Chin`, `Canopy`, `SpineHump`, `ArmL/R`) are `CSGCombiner3D`s that **intersect**
  three extruded `CSGPolygon3D` outlines: `SideProfile` (rotated Y 90°, polygon x = −z),
  `TopProfile` (rotated X −90°, polygon y = −z) and `FrontProfile` (polygon in XY, extruded along Z).
  Edit the outlines to reshape a part. `ArmR` is a copy of `ArmL`; keep them in sync.
- Cylinders use `rings = 0`; extra rings cost triangles and add nothing.
- Small 3D clutter lives under `SpineDetail` and `CockpitDetail`; engines have a two-ring `CowlFront`/`CowlRear` bulge (plain `hull_light`) and a torus `IntakeLip`.
- Flat detail (vents, hatches, panels, markings, canopy frames) is **not geometry** — it is
  drawn by the shaders as colour + bump (see `detail_lib.gdshaderinc`).
- Several things are positioned in fighter coordinates and must be updated if parts move:
  - surface-feature boxes in `hull_body.tres` (fuselage + spine hump), `hull_chin.tres` (nose chin), `hull_wing.tres`, `hull_root.tres`, `canopy_glass.tres`;
  - nacelle trim `bands` in `nacelle.tres` (engine-body local Y);
  - `ExhaustParticlesL/R` positions in `game/flight_level.tscn` (they sit at the nozzles).
- `fighter_controller.gd` stretches nodes named `ExhaustTrail`; `fighter_livery.gd` repaints
  any ShaderMaterial with a `base_color` or `body_color` uniform.

## Materials

- `hull_panels.gdshader`: triplanar (object-space) panel texture + surface features + cel lighting.
  Texture channels: R inset plates, G ink lines, B tone (> 0.9 = striped decal), A height.
- `nacelle.gdshader`: cylindrical-wrap panel texture + trim bands + cel lighting.
- `canopy.gdshader`, `intake_grille.gdshader`, `exhaust.gdshader`, `starfield.gdshader` (sky).
- `detail_lib.gdshaderinc` (shared): `bump_normal()` (tangent-free bump), `CEL_SHADING`
  `light()` function, and `DETAIL_FEATURES` surface-feature boxes. A feature is
  `center.xyz + kind` (0 paint, 1 raised, 2 recessed, 3 vent, 4 hatch), `half-size.xyz + relief`,
  `rgba` (alpha = coverage). The box's thinnest axis must face along the surface normal.

## Commands

```sh
# triangle/vertex counts per part
godot --headless --path . --script tools/count_triangles.gd
# 1080p still of any scene at a given frame (temporarily writes override.cfg, removes it after)
tools/render_frame.sh res://fighter/fighter_showcase.tscn 5 out.png
# 10 s turntable frames -> video: same override as render_frame.sh, then
godot --path . --write-movie out/frame.png --fixed-fps 60 --quit-after 600 res://fighter/turntable.tscn
ffmpeg -framerate 60 -i out/frame%08d.png -c:v libx264 -crf 18 -pix_fmt yuv420p video.mp4
# regenerate assets
uv run --no-project --with numpy python tools/generate_sfx.py
uv run --no-project --with numpy --with pillow python tools/generate_textures.py
```
ffmpeg isn't installed system-wide; `uv run --no-project --with imageio-ffmpeg python -c
"import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"` prints a usable binary.

## Gotchas (learned the hard way)

- **MCP `set_shader_param` mangles array uniforms** (saves a list of dicts, or zeros a
  `PackedVector4Array`). Write those `.tres` files by hand, using `PackedVector4Array(x, y, z, w, ...)`.
- **Running the game autosaves the editor's in-memory copies** of open resources and can overwrite
  edits made to those files on disk. Make edits through the editor (MCP), or use a new filename.
- `attach_script` on a node already in the tree doesn't run `_ready()` — save and
  `scene_open(force_reload=true)` (matters for `@tool` scripts like the terrain).
- After writing files on disk, run `filesystem_manage scan` (and `reimport` for textures/audio).
- **Movie Maker toggle** (editor top-right) silences all audio and makes every run record to
  `1.avi`. If sound "disappears", check it first.
- The editor embeds the running game in its Game tab, so the window can't be resized
  there (turn off "Embed Game on Next Play" for a free window).
- **Ink outline / depth texture (Compatibility renderer):** reconstruct with
  `ndc = vec3(uv, depth) * 2.0 - 1.0`. The depth buffer is coarse (~16-bit), so the outline ignores
  bends smaller than a few depth steps, and cameras use a large `near` (1–4 m). A tiny `near`
  (0.05) speckles every face with false lines.
- Cel lighting: Godot's default Lambert includes 1/π, so custom `light()` output is scaled by
  `cel_light_scale ≈ 0.3` to match. Don't add hard specular to the flat hull; it lights whole panels.
- Godot `Curve` resources clamp to 0..1 unless `max_value` is raised.
- Project texture mask maps are imported lossless with mipmaps, no VRAM compression, no alpha-border fix
  (compression/fixing corrupts packed channels).

## Conventions

- GDScript: typed, tabs, `##` doc comments on exports, matching the existing scripts.
- Keep generated assets reproducible: change the generator, not the output file.
- Don't commit `*.avi` or `override.cfg` (gitignored).
- Hand-written `.tres` edits are safe while the editor's copy is unmodified (separate Godot
  processes such as renders and game runs read the disk version), but the open editor keeps
  showing its cached copy. Writing under a new filename and reassigning it avoids both problems.
- The CSG triangle counter uses `bake_static_mesh()`; `get_meshes()` can return a stale result.
